IndustrialCtrl(项目根)
├─ Models          // 实体/枚举/工位模型
├─ Core            // 核心调度/工位管理器/业务规则
├─ IO              // 虚拟IO、PLC、运动卡硬件层
├─ Utils           // 日志工具、公共帮助类
└─ UI              // 所有窗体、界面控件事件IndustrialCtrl(项目根)

每层核心职责（帮你建立架构思维）
Models：只存数据、状态、工位实体，无复杂逻辑
Core：全局调度、工位互锁、流程控制、核心业务
IO：硬件隔离层，以后接 PLC / 板卡 只改这里
Utils：通用工具，日志、时间、通用方法
UI：只做显示 + 按钮点击，不写业务、不写状态判断


【UI层 定时器timer1 心跳驱动】
        ↓
【Core 层 StationManager 总管理器】
        ↓
遍历所有工位 → Task01 / Task02
        ↓
【Models 层 WorkStation 工位类】
        ↓
状态机 StateMachineTick() 循环判断
        ↓
        ├─ 读取 IO层 信号(启动/报警/完成)
        ├─ 执行步骤逻辑
        ├─ 状态切换
        └─ 输出日志到 Utils 日志工具



关键流程口诀（以后看任何工控代码都适用）
1.定时器是心脏：所有状态流转靠轮询
2.工位各自独立：Task01、Task02 互不干扰
3.硬件解耦在 IO：信号全部统一封装
4.业务集中 Core：互锁、全局规则放管理器
5.UI 只做展示：绝不嵌套 if/else 业务逻辑




快速读懂别人工控代码的极简步骤
核心前提（记住这句话）
所有工控设备代码，底层永远只有一套逻辑：
定时器轮询心跳 + 状态机 Switch 流转 + IO / 信号触发跳转 + 工位隔离 / 互锁
只要抓住这 4 点，再乱的代码你都能拆明白。
